# Mongo API Practice

A practice REST API for a product catalog and a simple store. It is built with Node.js, TypeScript, Express, and MongoDB via Mongoose.

Features:

- Browse, full-text search, create, and review products.
- Create and retrieve orders, with input validation and inventory reservation.
- Analytics reports for sales, products, categories, reviews, and stock.
- Request validation with Zod and centralized error handling.
- Configurable random data seeding with Faker.

## Requisitos

- Node.js `24.14.0` (version specified in `.nvmrc`).
- pnpm.
- A local MongoDB instance or one accessible via URI. Docker is optional for running MongoDB in a container.

## Installation

Install the dependencies and create the local configuration:

```bash
pnpm install
cp .env.example .env
```

Edit `.env` if MongoDB is not running at `localhost:27017` or if you want to change the API port. Available variables are described below.

### MongoDB with Docker

Start a local instance with a persistent volume:

```bash
docker run -d \
  --name mongo-practice \
  --restart unless-stopped \
  -p 27017:27017 \
  -v mongo-data:/data/db \
  mongo:7
```

By default, the API connects to `mongodb://localhost:27017/mongo_practice`. The `mongo-data` volume preserves data even if the container is removed.

If MongoDB is already installed or managed by another service, Docker is not required; update `MONGO_URI` in `.env`.

## Run the API

Development mode:

```bash
pnpm dev
```

By default, the API is available at `http://localhost:3000`. Check its status with `GET /health`.

Build and run the production version:

```bash
pnpm build
pnpm start
```

## Seed sample data

The seed script creates categories, users, products with reviews, and orders spanning the past year. Faker generates the data, and `SEED_VALUE` lets you reproduce the same random sequence.

**The seed script deletes all documents from the `users`, `categories`, `products`, and `orders` collections before inserting data. Run it only against a disposable database or after confirming you have a backup.** The script requires `SEED_RESET=true` to run.

With the `.env.example` configuration, this safeguard is enabled. Run:

```bash
pnpm seed
```

The project is built and then `dist/seed/seed.js` is executed. The defaults are 30 users, 100 products, and 200 orders. You can adjust them in `.env`:

```dotenv
SEED_USERS=30
SEED_PRODUCTS=100
SEED_ORDERS=200
SEED_VALUE=254
SEED_RESET=true
```

Supported limits: 1–5,000 users, 1–10,000 products, and 1–50,000 orders. To use a different random sequence on each run, remove `SEED_VALUE` or set a different seed.

## Environment Variables

| Variable | Default | Description |
| --- | --- | --- |
| `PORT` | `3000` | HTTP port for the API. |
| `MONGO_URI` | `mongodb://localhost:27017/mongo_practice` | MongoDB connection URI. |
| `SEED_RESET` | Unset | Must be exactly `true` to allow the seed script to clear the collections. |
| `SEED_VALUE` | Random | Faker seed for reproducible data generation. |
| `SEED_USERS` | `30` | Number of users generated by the seed script. |
| `SEED_PRODUCTS` | `100` | Number of products generated by the seed script. |
| `SEED_ORDERS` | `200` | Maximum number of orders generated by the seed script. |

## Endpoints

All resource endpoints use the `/api` prefix.

| Method | Route | Description |
| --- | --- | --- |
| `GET` | `/health` | API health status. |
| `GET` | `/api/products` | Lists active products; supports category, price range, and tag filters, as well as sorting and pagination. |
| `GET` | `/api/products/search?q=texto` | Full-text product search. |
| `GET` | `/api/products/:id` | Retrieves a product by ID. |
| `POST` | `/api/products` | Creates a product. |
| `POST` | `/api/products/:id/reviews` | Adds a review to a product. |
| `POST` | `/api/orders` | Creates an order and reserves stock. |
| `GET` | `/api/orders/user/:userId` | Lists a user's orders. |
| `GET` | `/api/analytics/revenue-by-category` | Revenue and units sold by category. |
| `GET` | `/api/analytics/top-products` | The five best-selling products. |
| `GET` | `/api/analytics/avg-order-value` | Average order value for users with recurring orders. |
| `GET` | `/api/analytics/product-ratings` | Review statistics by product. |
| `GET` | `/api/analytics/monthly-sales` | Sales grouped by month. |
| `GET` | `/api/analytics/low-stock` | Active products with fewer than ten units in stock. |

Requests with a body must send JSON with `Content-Type: application/json`. IDs and payloads are validated before reaching the controllers; validation errors include details in the response.

## Project Structure

```text
src/
  config/        MongoDB connection
  controllers/   HTTP adapters
  errors/        Application errors
  middleware/    Request validation and error handling
  models/        Mongoose schemas
  routes/        Express routes
  seed/          Test data generation
  services/      Queries and application logic
  validation/    Zod schemas
```
